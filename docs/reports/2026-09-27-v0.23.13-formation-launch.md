# v0.23.13 Formation launch verification

Verification of hydra-toon OST report 05's
[Python launch](https://github.com/animu-sphere/open-strata/issues/259) and
[Windows path depth](https://github.com/animu-sphere/open-strata/issues/260)
issues using the v0.23.13 implementation on Windows x86_64 with Python 3.13.14.
The real-artifact probe used a development binary built before the package
version bump, with the same launch/materialization implementation.

## Inputs and procedure

Copied the downstream `vrm-usdview` Formation and its material-probe scene into
a temporary project with a 111-character directory path. The Formation's declared command remained
`testusdview`, with no absolute interpreter or `runpy` wrapper. Artifacts were
already present in the local store:

| Component | Artifact digest |
| --- | --- |
| CY2026 OpenUSD 26.08 lookdev runtime | `sha256:b982656c07dd9147973e3c7197d9b050ee48dd1ac291988f7e6025c76c4a785b` |
| vrmImaging 0.9.0 | `sha256:3043a23979bf4d884807878247e221ef7d565548c547fef1ca15ce56117f6447` |
| Toon renderer 0.1.0 | `sha256:e91ac742b2b8e8b4db2144440d996adff6476fc6190626a543e5dfff7e77b1a7` |

Ran `formation lock`, `doctor`, `run -- testusdview --help`, and a
`QApplication` startup probe under `QT_QPA_PLATFORM=offscreen`, followed by
the declared command with the downstream render callback.

## Observations

- Lock creation and all four doctor checks passed.
- `testusdview --help` exited 0 using the discovered Python 3.13 interpreter;
  its renderer choices included `Toon`.
- `QApplication` initialized the `offscreen` platform plugin and exited 0.
- The runtime's `qwindows.dll` path was 105 characters under the short store
  root, independent of the manifest directory. Report 05's previous path was
  254 characters. No Qt path-length error occurred.
- The declared `testusdview` command reached the downstream test callback.
  The offscreen image-capture attempt exited 1 because the stage view's renderer
  was `None` at `IsConverged()`. This is not evidence of successful rendering;
  the full avatar/image acceptance remains a downstream task.
- Replaced only the temporary test callback with a renderer-registration check.
  The same declared command then exited 0, with empty stderr and both
  `HdStormRendererPlugin` and `HdToonRendererPlugin` registered. No interpreter
  override or launch wrapper was needed.

## Automated regression coverage

Formation CLI tests cover an extensionless Python script with a
missing producer shebang, its OpenUSD `.cmd` shim, argument preservation,
interpreter selection on `PATH`, machine-independent locks, missing/wrong-ABI
host Python, native-command launch, non-executable rejection, deep project
paths, fresh extraction and retained-tree isolation.

All 941 local workspace tests, formatting, clippy with warnings denied, and
`cargo deny check` passed. Third-party notices were regenerated with
`cargo-about 0.9.0`; only workspace package versions changed. Hosted CI also
runs the Formation fixtures on Linux, Windows, macOS arm64 and macOS Intel.

The real probe does not certify macOS/Linux graphics, the full avatar, or the
report's separate transitive duplicate-plugin and foreground-stream observations.
