# v0.23.8 renderer install-tree verification

## Scope and environment

Candidate verification of `ost 0.23.8` and renderer template 0.5.3 on Windows
with MSVC 14.51, NVIDIA RTX A5000, the `core` runtime and the existing `lookdev`
runtime with OpenUSD 26.08. A fresh `release-smoke` project was generated under
the OpenStrata working tree; the hydra-toon checkout was not modified.

The source request is
[hydra-toon report 02](https://github.com/animu-sphere/hydra-toon/blob/main/docs/reports/ost/02-2026-09-26-v0.23.7-report-01-reverified.md).

## Procedure and results

| Procedure | Observed result |
| --- | --- |
| Fresh template, core build and `ost test` | 3 of 3 CTests passed, including installed headless execution. |
| Core `ost validate` | Passed; `renderer.install_tree` PASS names the managed `ost-test` producer. GPU frame evidence also passed. |
| Unchanged core build, then validation | Passed; install-tree verdict and producer evidence retained. |
| Enable Hydra intent, build and test with `--profile lookdev --intent hydra` | 7 of 7 CTests passed, including OpenUSD 26.08 usdview smoke. |
| Hydra validation before and after an unchanged build | All 13 renderer assertions passed, including install-tree and host checks. |
| Alternate profile, then `ost lock` and `ost lock --check` | Build selected lookdev in `strata.lock`; explicit default lock refresh restored the original core bytes. |

The managed renderer lifecycle regression checks the install verdict in the
primary report, its test-completion digest binding, unchanged unrelated
assertions, repeated CTest with parallelism set to four, and validation after a
no-op build. An injected CMake install failure leaves the previous primary
report untouched and makes managed testing and subsequent validation fail.
Existing checks still reject modified evidence and incompatible prior build
completion records.

The full Rust workspace tests, Clippy with warnings denied, formatting,
documentation checks and dependency license/advisory checks passed. Third-party
attribution was regenerated for the workspace version; dependency versions did
not change.

## Limits

This is local candidate evidence, not a downstream run with the published
release. Existing renderer repositories must apply the template script change.
It does not establish the hosted renderer GPU/OS/OpenUSD matrix or new renderer
features. Project lock semantics remain unchanged.
