# v0.23.11 renderer Formation verification

## Scope

Hydra-toon [report 04](https://github.com/animu-sphere/hydra-toon/blob/main/docs/reports/ost/04-2026-09-26-v0.23.10-a-renderer-formation.md)
is tracked as OpenStrata issues #251–#255. The fixes cover target compatibility,
named-intent packaging, installed renderer discovery paths, independent profile
locks, installed-runtime explanation and canonical lookdev production.

## CLI and native evidence

- The local workspace suite passed 939 Rust tests; strict all-target clippy,
  generated documentation, relative links and eight producer-planner tests pass.
- The cross-platform Formation integration test drives `ost build --intent`,
  `ost package`, `ost plugin package`, artifact import, Formation resolve and
  Formation lock. It packages a real CMake install tree and an imaging fixture
  with its codeless schema closure. Placeholder SDK/library bytes are explicitly
  structural fixtures, not a native-loading claim.
- Native Windows x86_64 verification uses OpenUSD 26.08, a fresh renderer
  template instance (`release-smoke`) with a Hydra build intent, and the
  `material-adapter` imaging bundle with its `material-schema` dependency.
  Both default `strata.lock` files remain byte-identical after lookdev builds
  and packages. Default and lookdev lock checks pass.
- The renderer manifest records `hydra` and
  `lib/usd/hdReleaseSmoke/resources`. Its package and the imaging package import
  successfully. Formation resolve, lock and doctor pass.
- Inside `formation run`, `Plug.Registry` loads `hdReleaseSmoke` and
  `MaterialAdapterImaging`; `Tf.Type` resolves `MaterialAdapterAPIAdapter` and
  `UsdImagingGL.Engine.GetRendererPlugins()` includes
  `HdReleaseSmokeRendererPlugin`. This checks installed discovery and native
  loading through the composed environment, not merely package metadata.
- Repeating the component builds and packages against the published Windows
  runtime below also passes profile lock checks, Formation resolve/lock/doctor
  and both native plugin loads. A component built against the prior runtime is
  correctly rejected for its mismatched runtime digest.

The native session revealed an additional missing imaging-SDK context in
Formation validation; the fix now inspects the materialized runtime. Hosted
Windows CI also exposed short TEMP aliases versus canonical bundle roots;
materialization normalizes that identity before containment checks.

## Canonical runtime evidence

Windows and Linux x86_64 OpenUSD 26.08 lookdev GL runtimes were built from the
upstream `v26.08` tag with managed CY2026 dependencies, including oneTBB
2022.1.0, CPython 3.13 and the declared MSVC 19.40 / GCC 14.2 toolchains.
The archives include usdview, PySide6 6.8.3 and PyOpenGL 3.1.9.

The initial producer run exposed upstream `--imaging` disabling usdview.
The CLI now requires `--usd-imaging --usdview` for viewer-capable profiles
and rejects core/viewer-disabled requests. The release artifacts completed
the already-built SDKs with an incremental CMake install using
`PXR_BUILD_USDVIEW=ON`; build metadata records this completion and the original
producer revision. No compiler or dependency closure was substituted.

Both producer hosts pass consumer configure/link, OpenGL loader, physical
device and 64px `usdrecord` render checks. Linux uses the WSL D3D12 Mesa driver
on AMD Radeon graphics; Xvfb's llvmpipe is correctly rejected as physical GPU
evidence. Viewer Python import checks pass on both systems.

Repository: `oci://ghcr.io/animu-sphere/openstrata-runtime-cy2026-lookdev`.

is measured separately by `usdrecord`. Windows observes an NVIDIA RTX A5000;

After making the GHCR package public, anonymous digest pulls on both operating
systems also pass into separate empty stores. Registry credential variables are
removed for these checks; both the OCI manifest and expected artifact digest
are pinned. The same archives were independently materialized and exercised by
the clean-consumer checks above.

## Limits

The native component session does not claim hydra-toon's full VRM visual acceptance or macOS usdview/Metal
acceptance. The latter is required before declaring a canonical macOS lookdev
leaf.
