# v0.23.17 — Declared X11 host dependencies in installed library consumers

Fixes [issue #287](https://github.com/animu-sphere/open-strata/issues/287):
`ost library verify-consumer` could not find the host X11/Xt required by a Linux
runtime's MaterialX package, even with its declared development packages installed.

## Changes

- Linux runtimes declaring both `apt:libx11-dev` and `apt:libxt-dev` resolve
  their host X11/Xt with CMake's built-in FindX11 before loading package configs.
  System discovery is scoped to that probe; installed package discovery retains
  the declared library closure and selected runtime prefixes.
- Imported paths resolved on X11/Xt and their transitive target dependencies
  receive exact target/property/path allowances. A host include root such as
  `/usr/include` does not allow unrelated library targets or arbitrary files
  below that root. Later modifications of host target paths are checked too.
- `library-consumer.json` adds `runtime_host_requirements` and
  `runtime_host_paths`, retaining declared packages and resolved host target
  property paths even when a later consumer configuration fails.
- A Linux native regression exercises the Work → pxr → MaterialX → X11/Xt
  chain and consumer linking with real system development packages. Negative
  cases reject unrelated paths, modified X11 targets and ambient system packages.

## Compatibility and limitations

No library descriptor changes are required. The selected runtime must declare
both X11 development packages, and the host must provision them. Other host
packages do not automatically gain discovery or path allowances. Existing
runtime-aware Python resolution and imported-path checks remain in effect.

The regression uses synthetic package configs and real X11 libraries. Acceptance
of the original downstream package still requires a hosted rerun with its
locked OpenUSD runtime.
