# v0.23.8 - Renderer core install-tree evidence

## Objective

Resolve the new install-tree evidence request in
[hydra-toon report 02](https://github.com/animu-sphere/hydra-toon/blob/main/docs/reports/ost/02-2026-09-26-v0.23.7-report-01-reverified.md).
That report confirms all five report 01 requests are resolved in v0.23.7,
but a passing core install-tree CTest still leaves `renderer.install_tree`
as SKIP in `ost validate`.

## Shipped fixes

- Renderer template 0.5.3 copies the installed headless report's successful
  `renderer.install_tree` assertion into the primary `renderer-report.json`
  consumed by validation. The full installed report remains in the install
  prefix for diagnosis. Other GPU and Hydra assertions are preserved.
- Publication occurs only after successful installation and headless execution,
  with an explicit PASS in the installed report. The existing serial CTest
  property prevents competing primary-report writes; repeated tests remain
  idempotent. Managed `ost test` binds the updated report to its test producer,
  and unchanged builds retain that evidence.
- The [lock guide](../guides/examples.md#lock--reproducibility) answers the
  report's profile question: `strata.lock` records the last configured runtime,
  including profile overrides. Per-target locks remain separate. Run `ost lock`
  after alternate-profile packaging to restore the default pin before committing.
  Lock behavior and package/runtime identity enforcement are unchanged.

## Compatibility and limits

Workspace crates and CLI are version `0.23.8`; manifest and artifact formats
are unchanged. Upgrading the CLI does not rewrite existing scaffold sources.
Existing renderers must apply the change to
`validation/run-install-smoke.cmake.in`, reconfigure/build, then run `ost test`
and `ost validate`. Core install-tree evidence needs neither Hydra nor usdview;
unavailable GPU or host capabilities remain explicit SKIPs.

Local candidate verification is recorded in the
[install-tree report](../reports/2026-09-26-v0.23.8-renderer-install-tree.md).
A downstream rerun with the published template change and the broader hosted
renderer OS/OpenUSD matrix remain in the [roadmap](../roadmap/current.md).
