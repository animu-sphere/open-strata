# v0.23.15 — Scoped library dependencies, tool packaging and reusable source CI

Repairs workspace library dependency isolation, packaging for workspaces without
plugin bundles, and generated source-CI workflows. Also extends the canonical
lookdev producer plan and refreshes dependencies and third-party attribution.

## Changes

- Plain-library descriptors distinguish installed consumer dependencies in
  `requires.libraries` from `requires.build_libraries` and
  `requires.test_libraries`. Graph validation checks every scope. Build-only
  dependencies are recorded in build provenance without entering the published
  consumer closure; test-only dependencies are available to the directly selected
  library's tests without being inherited by prerequisites or packaged consumers.
- Scoped library builds enable `BUILD_TESTING` for the selected subject and
  disable it for prerequisites and installed-consumer verification. Test evidence
  checks the dependency closure and rejects stale or testing-disabled builds.
  Packaging no longer requires test-only dependencies to remain installed.
- `ost plugin package --workspace` packages declared tools in workspaces with no
  plugin bundles. Each tool carries its descriptor, declared executables,
  materialized runtime directories, library requirements, checksums and evidence.
  JSON package entries identify tool members and their archive digests for
  artifact import and downstream `requires.tools` pins.
- Generated GitHub workflows define matrix keys referenced by conditional steps,
  including workspace pyramid levels and optional runner profiles. Regression
  coverage runs actionlint against generated workflow expressions.
- Formation lifecycle tests isolate concurrent sandboxes even when the host
  clock returns identical timestamps, fixing macOS Intel CI interference.
- `ost ci generate github --reusable-source` emits source CI with
  `workflow_call`: PR callers select PR lanes, main pushes select main lanes,
  and manual callers select all source lanes. Unsupported caller events or
  missing matching lanes fail explicitly. Support and trusted-release workflows
  retain their own triggers.
- The OpenUSD 26.08 lookdev producer matrix declares Vulkan leaves for Linux and
  Windows x86_64, with explicit producer commands and planning coverage.
- Cargo dependencies and pinned GitHub Actions are refreshed, including ureq
  3.5.0, with matching third-party notices.

## Compatibility and limitations

Existing `requires.libraries` declarations retain their installed-consumer
meaning. Move build-only and test-only requirements to the new lists deliberately;
an identity may appear in only one scope. CMake projects should guard test-only
package discovery and targets with `if(BUILD_TESTING)`.

Existing generated workflows must be regenerated to receive the matrix fixes.
Repeat `--reusable-source` on every regeneration when using a downstream
dispatcher; omitting the flag selects direct triggers. Path classification and
required-result aggregation remain the dispatcher's responsibility.

Declaring Vulkan producer leaves does not publish runtime artifacts or establish
physical-device rendering acceptance. Each host still needs its Vulkan SDK,
device/display checks, publication and recorded digest pins. Real downstream
installed-consumer and GPU/host acceptance remains separate from fixture tests.
