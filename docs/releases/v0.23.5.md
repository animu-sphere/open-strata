# v0.23.5 - Root suite external members and target-local output stages

## Objective

Close the OpenStrata defects in the [VRM report 46](https://github.com/animu-sphere/usd-vrm-plugins/pull/226) and [MMD report 01](https://github.com/animu-sphere/usd-mmd-plugins/blob/main/docs/reports/ost/01-2026-09-24-v0.23.3-a-bundle-is-staged-in-its-source-tree.md).

## Shipped fix

- `ost configure` and the root `ost build` now materialize every digest-pinned
  `requires.bundles[].artifact` and `requires.tools[]` declared by workspace
  bundles. The same artifact identity, runtime, target, component and descriptor
  checks used by member sessions apply.
- The generated root CMake toolchain exports
  `OPENSTRATA_EXTERNAL_BUNDLE_<id>_ROOT` and
  `OPENSTRATA_EXTERNAL_TOOL_<id>_DIR` cache paths. A tool with executables in
  multiple directories also exports `OPENSTRATA_EXTERNAL_TOOL_<id>_DIRS` as a
  CMake list. Root CMake suites can use these paths in
  `ENVIRONMENT_MODIFICATION`, including suites that deliberately remove a path.
  Removing a pin clears its old cache variable on the next configure.
- Bundle registration, libraries, Python files and declared runtime libraries
  are staged per target after a managed build. Member tests, run sessions and
  packages use the selected stage; source-tree generated outputs are no longer
  required. Root-built tools likewise stage their managed executables per
  target before tests and packaging consume them.

## Compatibility

- Workspace crate and CLI versions are `0.23.5`. Manifest, artifact and lock
  formats are unchanged; existing artifact pins need no revision.
- Workspaces without external bundle or tool pins do not gain new toolchain
  variables. Root CMake test authors must reference the exported paths to bring
  external suites into root CTest discovery.

- Rerun MMD source tests, packaging and a second target against the published
