# v0.23.14 — Renderer sessions and runtime publication retention

Closes hydra-merlin report 13's runtime-retention and evidence-classification
requests, and the related renderer workflow issues
[#265](https://github.com/animu-sphere/open-strata/issues/265),
[#266](https://github.com/animu-sphere/open-strata/issues/266) and
[#267](https://github.com/animu-sphere/open-strata/issues/267).

## Changes

- Renderer workflows add their adapter to the intent's declared CMake list.
  Renderer template 0.5.4 enables requested adapters while preserving explicit
  options for other adapters. Hydra and viewport can be built together.
- Named renderer workflow trees are isolated. Viewport with --intent hydra uses
  build/&lt;target&gt;--hydra--renderer-viewport; the matching validation command is
  ost validate --intent hydra--renderer-viewport. Ordinary build, test, package
  and validate --intent hydra retain their own tree. Hydra view uses the
  corresponding --renderer-hydra2 suffix.
- Renderer view and viewport accept repeatable --with inputs: bundle
  directories (including managed target stages), packaged workspace products,
  and local sha256: plugin/product artifact digests. Dependencies,
  identity/imaging conflicts, capabilities, archive integrity and packaged
  runtime provenance are checked before building. Launch records carry the
  composition and environment contributions.
- Renderer checks expose producer_kind and verification_class in JSON and
  human output. Classes are completion-bound, attached-external and unbound;
  provenance unavailable for an older merged assertion remains unknown/unbound.
  An unbound primary report in a managed tree emits a structured warning;
  --strict-renderer-evidence makes it a failure. Non-OST producer kinds named
  managed or managed-* are rejected.
- Artifact retain preserves exact OCI manifest bytes under a digest-derived
  tag and verifies the result. Both runtime publishers retain previous leaf
  manifests before moving tags, then journal old/new pins, reasons and a
  minimum 180-day retention window. Tag-family changes accept -MigrationMap.
- Known missing legacy Windows runtime pins have a
  [machine-readable migration record](../../support/runtime-migrations.json).
  A matching 404 reports prior publication and the replacement pin; an unknown
  reference explicitly keeps its publication history unknown.

## Compatibility and limitations

Existing project manifests and artifacts remain readable. Regenerate or apply
the template adapter option block to existing generated projects; updating the
CLI does not rewrite project-owned CMake. If an older viewport invocation
already changed an ordinary intent cache, configure a fresh tree before using
it again. New workflow isolation prevents subsequent contamination.

Retention prevents deletion caused by superseding an untagged manifest; registry
administrators must preserve the retention tags and their reachable blobs.
Already missing historical bytes cannot be reconstructed from replacement
builds. Revalidate replacements before updating digest pins. Publisher journals
must be committed to the migration catalogue when announcing a republish.

Regression coverage exercises additive options, isolated preflight identities,
bundle/product sessions, corrupt artifacts, evidence warnings/strict failure,
and exact OCI retention across a leaf republish. Real downstream GPU and
usdview acceptance remains a separate host measurement.
