# v0.23.6 - Workspace bundle package output consistency

## Objective

Fix the product-package regression in [VRM report 47](https://github.com/animu-sphere/usd-vrm-plugins/blob/main/docs/reports/ost/47-2026-09-24-v0.23.5-the-bundle-reaches-the-suite-and-the-schema-stage-loses-a-file.md). A workspace-installed schema bundle recorded MSVC's `lib/vrmSchema.exp` from its source tree, but its package used an install stage without that linker by-product and failed with `PLUGIN_PACKAGE_OUTPUT_MISMATCH`.

## Shipped fix

- A dependency bundle still installs into the shared workspace prefix for later members to link. It also installs into its own target-local bundle stage.
- Managed build completion records the target-local stage when it contains the bundle registration. Packaging reads that same stage, so build provenance compares the files actually installed for the bundle. Files omitted by `cmake --install`, including MSVC `.exp` by-products, are not claimed as package outputs.
- The output comparison still rejects modified or missing staged files after the managed build.

## Compatibility

- Workspace crate and CLI versions are `0.23.6`. Manifest, artifact and lock formats are unchanged; existing artifact pins need no revision.
- Legacy bundles without install rules retain source-tree output handling.
