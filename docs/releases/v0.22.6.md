# v0.22.6 - Render-probe prerequisites and physical-device evidence

## Objective

v0.22.6 is a patch release for the next validation blocker exposed by USD VRM
source CI after v0.22.5 selected the correct Python interpreter. A host missing
the Qt bindings used by `usdrecord` must report an unmet probe prerequisite,
and a software OpenGL context must not be reported as a physical device.

The fix landed in [PR #200](https://github.com/animu-sphere/open-strata/pull/200).
The [investigation report](../reports/2026-08-26-usd-vrm-ci-render-prerequisites.md)
records the failing downstream jobs and local before/after evidence.

## Completed capabilities

- **Qt prerequisite preflight.** Python `usdrecord` probes check the required
  PySide6 OpenGL imports, with the same PySide2 fallback as the installed tool,
  under the resolved interpreter and runtime environment. Preflight and rendering
  share one child process and the existing timeout.
- **Explicit missing-prerequisite skips.** When neither binding imports, a
  dedicated exit code together with a diagnostic marker produces
  `openusd-render: skip`. The detail names the interpreter and missing Qt
  prerequisite and states that no render was attempted. Native tools and opaque
  shims retain their existing launch path; actual tool, pxr, and Hydra failures
  remain failures.
- **Software renderers are not physical-device evidence.** OpenGL observations
  of GDI Generic, llvmpipe, or softpipe are explained skips and cannot enable
  the render probe. Hardware renderer observations remain eligible. A software
  renderer's ability to render does not establish a physical GPU observation.
- **Regression coverage.** Isolated subprocess tests cover missing Qt, PySide6,
  PySide2 fallback, and tool failure. Device tests distinguish software renderers
  from NVIDIA and AMD observations; skip detection requires both the dedicated
  exit code and marker.

## Compatibility notes

- Artifact, runtime, and component contracts are unchanged. This release does
  not republish runtime artifacts or change downstream digest pins.
- Validation may now succeed with an explained render or device skip on a host
  lacking the required Qt bindings or a physical OpenGL device. A skip is not
  render success and does not claim a frame or physical-device evidence.
- Consumer observations still do not rewrite immutable producer identity.
  Export gates continue to require positive device/render evidence; validation
  exit policies are unchanged.
- No new dependency or toolchain change is included.

## Known limitations

- Local verification used the pinned Windows OpenUSD 26.08 runtime: deliberately
  unavailable Qt changed from a render failure to an explained skip, and the
  normal Qt/NVIDIA RTX A5000 environment rendered a real frame. This does not
  establish hosted Windows/macOS render support.
- Downstream USD VRM PR #140 still needs its OST bootstrap and hand-authored
  release pins updated, generated workflows refreshed, and source cells rerun
  with this release. Later build/test failures may remain behind the former
  validation blocker.
- The runtime-composition plan moves one slot: locked composed runtime is now
  v0.22.7, SDK layout v0.22.8, geospatial dogfood v0.22.9, consumer packaging
  v0.22.10, and runtime UX/diagnostics v0.22.11. DCC host adapters remain v0.23.0.
- Cross-repository composition acceptance, the outstanding canonical runtime
  publication/validation work, and the CI OpenUSD requirements and install-data
  filter requests remain in the [current roadmap](../roadmap/current.md).
