# v0.22.8 - Geospatial runtime dogfood

## Objective

Use the locked composition and native SDK shipped in v0.22.7 against real,
independently packaged OpenUSD geospatial components. The acceptance target is a
canonical OpenUSD 26.08 runtime plus the HTTP resolver, point-cloud file formats
and GeoTIFF support, followed by a self-contained export and clean reconstruction
with the exact same runtime identity.

The dogfood exposed one generic composition defect: a workspace aggregate
product retained its member archives but did not install their payloads into the
outer artifact paths advertised by the product contract. v0.22.8 corrects that
behavior so aggregate products can be consumed directly.

## Implemented capabilities

- Workspace aggregate products still retain each exact member archive for
  provenance and inspection, and now also extract verified member payloads into
  the aggregate artifact's declared install destinations.
- Aggregate packaging rejects missing mappings and conflicting output ownership
  before publication. Conventional library and Python environment paths are
  advertised only when the aggregate archive actually owns descendants there.
- Native SDK validation ignores OpenUSD's installed
  `resources/codegenTemplates/plugInfo.json`: it is a source template containing
  unresolved generator placeholders, not runtime plugin metadata.
- Lifecycle and runtime-composition regressions cover aggregate product payload
  installation, direct composition, retained members and SDK validation.

## Geospatial acceptance

The Windows x86_64 / Python 3.13 acceptance composed these independently
packaged inputs:

| Component | Version | Artifact digest |
| --- | --- | --- |
| Canonical OpenUSD runtime | 26.08 | `sha256:51c19df2725955adfc3ef2e96ba6da6561d332a923275eb133c3802a1f659a1c` |
| USD HTTP Resolver product | 0.5.0 | `sha256:2f9887eff977d1a800b23a0a0c35d578097c465535a933aa407f31644ee064c8` |
| USD Point Cloud Plugins product | 0.11.0 | `sha256:9954ff6788ae1987203bd05e8753c8265523cbad65c2f0a802bbfadb05bbef9e` |
| USD Raster Plugins product | 0.1.0 | `sha256:39c9d553ca60dc5d1f02e698377622d7567574c950d98a3306a010ca97819b28` |

- Component-owned probes loaded the resolver and packaged OpenUSD plugins from
  the composed prefix. LAS, LAZ, PLY and COPC fixtures produced the expected
  three-point content; GeoTIFF reported a 2 by 2 raster, EPSG:32654 and the
  expected geotransform.
- The resolver probe opened a relative sublayer over loopback HTTP in fresh
  processes. The cold pass transferred 73 bytes; the warm pass transferred no
  body bytes and reused the persistent cache.
- COPC Tier 2 exercised local and HTTP reads. Range requests were observed,
  strong revisions A and B produced distinct stable validation tokens, and a
  weak-validator revision remained unstable. All reads matched the local point
  digest. The tiny 814-byte fixture intentionally does not claim transfer
  selectivity below the full source size.
- The composed runtime identity was
  `sha256:904b8c12be5668fde17eda3f49c22b5cc30a253a5ffd3cf851d136ea7457f6bc`.
  Its self-contained artifact digest was
  `sha256:e0bc2fb1c6da23e8e3c722eefd6e6b0623aa7c0d0679e41e30a82152e61e1c62`.
  Importing only that artifact into an empty OST home reconstructed and
  SDK-validated the exact runtime identity without producer build trees or
  component caches.

## Compatibility and limitations

- This release changes aggregate product layout. Existing leaf artifacts and
  v0.22.7 composition locks retain their identities; repackage an aggregate
  product with v0.22.8 to make its mapped payload directly composable.
- The geospatial evidence above is Windows x86_64 / Python 3.13. It does not
  establish equivalent Linux or macOS component availability.
- The HTTP acceptance used a local measured origin so byte counts and validator
  revisions were deterministic. It proves packaged HTTP behavior, not a public
  service's availability or performance.
- COPC generated-cache production remains converter-owned. Resolver persistent
  cache miss-to-hit behavior and COPC stable/unstable source decisions are
  reported separately rather than being conflated into one cache claim.
- The OpenUSD code-generation template exclusion is exact and does not weaken
  validation of installed runtime `plugInfo.json` files.
