# v0.23.1 - Runtime consumer validation repair

## Objective

Let the generated CI runtime validation step measure the materialized prefix
that subsequent consumer builds actually use, including its repair of stale
OpenUSD CMake paths from older published artifacts.

## Shipped fixes

- `ost runtime validate` now applies the same guarded Python include and
  install-prefix relocation as `ost configure` and `ost plugin build` before
  `consumer-configure` and `consumer-link`. This unblocks Linux and Windows
  lanes that pulled older 26.08 artifacts with producer-local CMake paths.
  The repair stays silent under `--json`, preserving a single JSON document.
- A failed CMake configure claim now reports the first CMake error and its
  context, instead of losing it beneath trailing unused-variable warnings.
- The `file://` artifact documentation and missing-manifest hint now identify
  the package output directory containing `manifest.json`; a library uses
  `dist/<library>/<version>/<target>/`, rather than the `dist/` root.

## Compatibility

- Workspace crate and CLI versions are `0.23.1`.
- Existing v0.23.0 runtime, artifact, workspace, and lock identities remain
  valid. No republish is required for the consumer-side repair.

## Known limitations and follow-through

- Older published OpenUSD artifacts still contain producer-local paths in
  their immutable bytes. The local repair makes their materialized prefixes
  consumable; republishing those artifacts with portable exports remains
  separate work.
- Hosted Linux, Windows, and macOS acceptance of the three downstream
  repositories' re-pin is pending after publication.
