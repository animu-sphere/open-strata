# v0.23.3 - Tool library edges and runtime-safe build trees

## Objective

Close the two P1 defects found while `usd-vrm-plugins` migrated motion
libraries under v0.23.2: tool-only library declarations were ignored, and a
reused CMake tree could compile against a runtime different from the one in
`target.lock.json`.

## Shipped fixes

- Workspace graph validation now includes every tool's `requires.libraries`
  edges. A missing, incompatible or malformed library requirement fails the
  same graph check as one declared by a bundle or library. `ost library pull`
  and root `ost configure`/`ost build` include artifact pins declared only by
  tools in their workspace union, so their prefixes reach the root CMake tree.
- Generated toolchains record the configured runtime digest and prefix in
  `CMakeCache.txt`. Before reuse, `ost configure` and `ost build` discard a
  managed tree whose markers differ or are absent, allowing CMake to resolve
  `pxr_DIR`, `TBB_DIR` and other cached package paths from the selected runtime.
- `runtime validate` marks `layout-complete` as failed when a real runtime's
  declared `bin` or `lib` directory is empty. This detects the directory
  skeleton left by the temporary-file cleanup reported downstream.

## Compatibility

- Workspace crate and CLI versions are `0.23.3`.
- v0.23.2 runtime, artifact, workspace and lock identities remain valid. No
  republish or re-pin is required.
- The first configure of a build tree created before v0.23.3 will rebuild that
  tree, since its CMake cache has no runtime identity markers.

## Known limitations and follow-through

- The downstream tool-only migration and an independent installed consumer
  still need to be run against the published v0.23.3 executable.
- `layout-complete` checks that `bin` and `lib` contain entries; it is not a
  full artifact-file integrity check. `runtime validate` continues to
  provide the deeper runnable and consumer checks.
- The remaining limitations listed in [v0.23.2](v0.23.2.md) still apply.

## Downstream evidence

[usd-vrm-plugins ost report 44](https://github.com/animu-sphere/usd-vrm-plugins/blob/main/docs/reports/ost/44-2026-09-23-v0.23.2-a-tool-edge-reaches-nothing-and-a-tree-keeps-its-runtime.md)
reproduced both P1 defects and the empty-directory validation gap. Its root
build passed 75 tests against four external packages after the stale CMake
cache was removed; this release automates that invalidation and extends the
dependency set to tool members.
