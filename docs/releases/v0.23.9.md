# v0.23.9 - UsdImaging plugin bundles

## Objective

Address [USD VRM Plugins report 49](https://github.com/animu-sphere/usd-vrm-plugins/blob/main/docs/reports/ost/49-2026-09-26-v0.23.8-no-plugin-kind-for-a-usdimaging-adapter.md):
an external UsdImaging adapter can now declare a bundle descriptor and participate
in the existing build, test, dependency, package and aggregate product lifecycle.

## Shipped capabilities

- `kind: usd-imaging` accepts API-schema and prim adapters. Singleton provisions
  are `usd-imaging:<apiSchemaName>` and `usd-imaging-prim:<primTypeName>`.
  Workspace graphs and explicit composed sessions reject duplicate owners;
  artifact component contracts preserve the singleton keys.
- L0 `imaging.metadata` checks that `provides` exactly matches unique adapter
  metadata, rejects empty keys and external adapters claiming `isInternal`.
  Schema providers use ordinary `requires.bundles` edges, including staged
  registration resources in standalone packages.
- Imaging bundles intrinsically require `hydra-preview`; an omitted requirement
  in a hand-authored descriptor cannot bypass profile selection. L1
  `runtime.usd_imaging` and the build preflight require the usdImaging SDK.
  `runtime validate` checks it for runtimes promising imaging capabilities.
- L2 `imaging.registration` builds and runs a native checker against the selected
  SDK. It registers plugins, checks `HasAPISchemaAdapter` / `HasAdapter`, and
  constructs each adapter. API-schema definitions must exist in the session.
  Disabled external plugins (`USDIMAGING_ENABLE_PLUGINS=0`), missing schemas,
  missing registrations, broken factories and unavailable build tools fail with
  process evidence. L3/L4 retain the ordinary stage-read checks.
- `ost plugin new usd-imaging` supplies the `usd-imaging-cpp` 0.1.0 registration
  skeleton. It requires `--schema-bundle` and `--schema-type` (the registered
  API schema name), records provenance, installs its bundle, and avoids the
  OpenUSD 26.08 `hd/retainedDataSource.h` C++20 incompatibility.

## Compatibility and limits

The CLI and workspace crates are `0.23.9`. Existing plugin kinds and manifest
versions retain their behavior. Older CLIs cannot read `usd-imaging` descriptors.
Select a profile promising `hydra-preview`, normally `--profile lookdev`, backed
by an imaging SDK. The template's OpenUSD range is `>=26.05,<27.0`.

L2 requires CMake, Ninja, a C++ compiler and the runtime's development headers
and libraries, including for `--from-package`. It uses a private temporary build
tree and removes that tree afterwards. No Python binding for the adapter
registry is assumed. Missing tools fail rather than claiming discovery passed.

The template registers an empty adapter; implement data sources, invalidation,
and application-specific scene-index tests. API-schema adapters need
`UsdImagingStageSceneIndex`; legacy `UsdImagingDelegate` does not consult them.
The checks do not certify rendered output or scan arbitrary ambient plugin paths
for ownership conflicts. Local native evidence covers Windows/OpenUSD 26.08;
Linux/macOS native downstream acceptance remains open. Report 48's producer
RUNPATH cleanup is tracked separately.
