# v0.22.5 - Consumer-lane corrections from downstream dogfooding

## Objective

v0.22.5 is a patch release carrying the corrections a downstream consumer found
by running the v0.22.3/v0.22.4 lanes against the canonical CY2026 runtimes on
real hosts (USD VRM report 36). Every finding is a *consumer* defect — the
published artifacts were correct throughout and none was republished — and every
one of them made `ost` report something about a runtime, a workspace, or an
artifact that was not true of it.

The theme is the same in all four: a check that could not run, or a tool reading
its own inputs wrongly, must not be reported as the thing it was measuring
failing.

## Completed capabilities

- **The render probe runs under the runtime's own declared Python.**
  `ost runtime validate` launched `usdrecord` through the launchers OpenUSD
  installs beside it — on Windows a shim that is literally
  `@python "%~dp0usdrecord" %*`, elsewhere a shebang naming the *producer's*
  interpreter path — so the probe ran under whatever `python` the host happened
  to present first. A hosted runner defaulting to 3.12 therefore failed a py313
  runtime with `ImportError: DLL load failed while importing _tf`, and reported
  it as the **runtime** failing validation on ten of seventeen cells. The
  interpreter is now resolved the way `ost plugin run` resolves one — the
  bundled interpreter first, else a host CPython matching the runtime's ABI —
  and the script is handed to it explicitly. Installed tools are classified by
  their shebang rather than by extension, so a native binary is never handed to
  an interpreter.
- **A probe with no satisfying interpreter is skipped, not failed.** A host that
  can offer no interpreter matching the runtime's declared Python reports
  `openusd-render` as **skipped**, naming the version required and the
  interpreters searched. This is the rule v0.22.4's `1ff348a` established one
  layer up, applied to the layer above it: a probe that could not run has
  observed nothing about the runtime. Both the passing and failing details now
  name the interpreter used, so an environment failure is not read as a runtime
  one.
- **Generated CI installs the declared host Python before validating.**
  `ost ci generate github` emits the `host_python` `setup-python` step ahead of
  `ost runtime validate`, so a cell that declares which interpreter the lane uses
  is not validated against the runner's accidental default. This is a
  consistency fix, not a substitute for the one above — the probe pins its own
  interpreter either way.
- **Wildcard member patterns ignore residue.** A `[workspace].members` wildcard
  that swept up a `__pycache__` refused the entire workspace graph, including
  for commands that would never have touched that directory — which pushed
  projects into naming every member by hand. A wildcard is now treated as a
  filter over whatever the tree holds rather than an assertion about every
  directory it touches: a matched directory with no member descriptor is
  skipped, a **literal** member without one still fails and the error names the
  pattern that selected it, and a pattern that reaches directories but selects no
  member is `WORKSPACE_MEMBER_PATTERN_EMPTY` listing what it did reach.
  `__pycache__` also joins the scan exclusion list.
- **A per-member build tree outliving its compiler is reconfigured.** Upgrading
  a compiler in place left every `build/<target>` cache naming a `cl.exe` that no
  longer existed, and the recorded compiler lock could not see it: under the
  default `host` policy the lock records no compiler path at all, so its
  fingerprint was unchanged. `ost` loaded the *new* toolchain's environment and
  then handed CMake a cache naming the old one, failing as a raw
  `The CMAKE_CXX_COMPILER … is not a full path to an existing compiler tool` one
  directory at a time. Per-member verbs now drop a tree whose cached
  `CMAKE_CXX_COMPILER` is an absolute path that no longer resolves, and say so in
  `ost`'s own words.
- **Compatibility-identity refusals name the provider and the condition.**
  `ARTIFACT_MANIFEST_INVALID`'s "unverified or contradictory provider versions"
  named neither which provider nor which of the two conditions held, and the two
  point at opposite owners: *unverified* is a predicate the consumer evaluates,
  *contradictory* is a claim about the bytes. That sentence cost a downstream
  consumer a wrong diagnosis — a macOS leaf was read as needing republication
  when the artifact was correct and v0.22.3's wildcard-constraint comparison was
  not. Every refusal now names one provider, its declared constraint and observed
  version, and ends in the condition that held. The same message reaches
  `ost runtime validate`'s `openusd-compatibility-identity` check and
  `set_openusd_compatibility`.

## Compatibility notes

- This is a patch release on the v0.22.4 artifact, runtime, and component
  contracts. The approved OpenUSD, platform, toolchain, provider, graphics,
  artifact, and evidence requirements are unchanged, and no runtime artifact was
  republished — the canonical 16-leaf matrix digests are exactly those v0.22.3
  published.
- `openusd-render` can now report **skipped** where it previously reported
  failed, on a host with no interpreter satisfying the runtime's declared Python.
  A skipped check does not fail validation, so a lane red for this reason turns
  green without any contract edit.
- A `[workspace].members` wildcard that previously failed with
  `WORKSPACE_MEMBER_DESCRIPTOR_MISSING` on a descriptor-less directory now
  skips it. The fail-closed half is unchanged: a descriptor no pattern covers is
  still `WORKSPACE_DESCRIPTOR_NOT_DECLARED`, and a literal member without a
  descriptor is still an error.
- Text of the compatibility-identity refusal changed. Consumers matching on the
  coded error (`ARTIFACT_MANIFEST_INVALID`) are unaffected; consumers matching on
  the phrase "unverified or contradictory provider versions" are not.
- A per-member build directory may be deleted and reconfigured on the next verb
  when its cached compiler is gone. This costs one configure and replaces a hard
  failure.

## Known limitations

- Two asks from the same report remain open, both P3 and both carried in
  [current.md](../roadmap/current.md): a CI cell cannot declare the required
  normalized OpenUSD cell/version for `ci generate` to render into the pull, and
  `[[workspace.install_data]]` cannot express an include filter the way a
  `cmake --install` rule can.
- v0.22.4's cross-repository composition acceptance and the Linux/Windows halves
  of the canonical 16-leaf publication pass are unchanged carry-over; corrections
  found there belong to v0.22.6.
- The runtime-composition series slides one slot: locking a composed runtime is
  now v0.22.6, and the ladder through v0.22.10 is in the
  [runtime-composition plan](../roadmap/runtime-composition.md).
- DCC host adapters and the pinned host support matrix remain deferred to
  v0.23.0.
