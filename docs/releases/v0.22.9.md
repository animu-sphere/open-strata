# v0.22.9 - Consumer packaging and downstream intake

## Objective

Derive registry-neutral consumer packages from one canonical OST runtime
identity, prove clean consumers without exposing OST internals as their public
API, and reconcile every outstanding reference-repository OST report with the
forward roadmap.

## Shipped capabilities

- Added one consumer manifest that retains the exact runtime artifact digest,
  runtime and component identities, target, entrypoints, provenance, evidence
  and SBOM references across native, Python and JavaScript distributions.
- Verified installed native CMake entrypoints and exact runtime identity from a
  relocated clean consumer.
- Assembled deterministic Python wheel and npm archives with package-private
  `verify -> extract -> activate` loaders, then installed and executed them in
  isolated consumer stores.
- Added installed ordinary-library consumer verification from only the declared
  package closure, including generated CMake configure/link/optional-execute
  probes and structured results.
- Required normalized OpenUSD CI cells and versions where OpenUSD support is
  declared, and added filtered `[[workspace.install_data]].include` staging.
- Hardened downstream packaging against symlink escape and stale Windows PDB
  reuse, and made OCI response-body timeouts reflect idle progress rather than
  total transfer duration.

## Downstream report intake

All 71 non-index OST reports from USD VRM Plugins, hdMerlin, USD 3DGS Plugins,
USD Point Cloud Plugins, USD HTTP Resolver, USD Raster Plugins, USD Vector
Plugins and USD Stage Runner were checked against current source, tests and
release records. Resolved and superseded requests remain release history;
unimplemented reusable asks are deduplicated in the
[downstream report intake](../roadmap/downstream-report-intake.md) for v0.22.10
and v0.23.0.

## Compatibility

- Workspace crate and CLI versions are `0.22.9`.
- v0.22.8 runtime, artifact, lock and aggregate-product identities remain valid.
- Consumer packages are derived views of canonical OST artifacts; their
  ecosystem package version is not a replacement for the OST digest or lock.

## Known limitations

- This release proves deterministic local assembly and clean-consumer behavior;
  publication to each external ecosystem registry is not claimed as release
  evidence. Registry-facing acceptance remains in v0.22.10.
- Exported OpenUSD CMake metadata can still retain producer-absolute Python
  paths. Package/runtime lock enforcement and normalized lock checking also
  remain v0.22.10 work.
- Runtime-free CI, expanded release-lane verbs and the first-class `usdview`
  host-add-on model remain scheduled work.

## Verification

The release gate includes locked workspace tests and clippy, deterministic docs
generation, link and documentation-consistency checks, and diff hygiene. Native
lifecycle coverage remains host-capability dependent as documented in the root
README.
