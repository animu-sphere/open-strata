# v0.23.4 - Runtime-safe member builds and external bundles/tools

## Objective

Close the three asks in `usd-vrm-plugins` report 45: repair standalone CMake
runtime reuse, consume published bundles across repositories, and make
published tools available to tests.

## Shipped fix

- Both per-member build paths check the runtime digest and prefix before
  writing the toolchain or invoking CMake. A changed runtime discards the
  member's managed CMake tree.
- A member tree now carries a separate runtime identity record written only
  after a successful configure. Trees made by v0.23.3 lack this record and are
  rebuilt once. This also repairs trees whose cache markers already name the
  selected runtime while `pxr_DIR` still points at an older one.
- `--dry-run` leaves the existing build tree alone.
- `requires.bundles[].artifact` accepts the same digest and per-target pin
  format as external libraries. The workspace graph validates the pin;
  session commands materialize the exact published bundle after checking its
  archive, component, version, target, runtime and schema contract. Packaging
  carries its USD registration, libraries and transitive packaged closure.
- `requires.tools[]` pins a published tool for tests. Test and run sessions
  materialize and verify the tool, then prepend its executable directory to
  `PATH`. A bare test command resolves against that composed session path.

## Compatibility

- Workspace crate and CLI versions are `0.23.4`.
- Runtime, artifact, workspace and lock identities remain valid. No artifact
  republish or re-pin is required.
- Existing bundle manifests remain valid. External bundle/tool pins are
  additive fields under `openstrata.plugin/v1alpha1`.
- The first standalone build of an existing bundle or library rebuilds its
  per-member CMake tree. Later builds reuse a tree whose runtime identity
  still matches.

## Known limitations and follow-through

- The standalone VRM build sequence still needs a rerun against the published
  v0.23.4 executable, including an intentionally stale tree.
- The published `execMotion` bundle and `motion_convert` tool still need an
  end-to-end downstream migration and installed-consumer check against v0.23.4.
- Other open downstream acceptance items remain in the
  [current roadmap](../roadmap/current.md).

## Downstream evidence

[usd-vrm-plugins OST report 45](https://github.com/animu-sphere/usd-vrm-plugins/blob/main/docs/reports/ost/45-2026-09-23-v0.23.3-a-tool-edge-arrives-and-a-bundle-tree-keeps-its-runtime.md)
reproduced a bundle cache with the new artifact runtime digest and an old
adopted-runtime `pxr_DIR`, then passed all six standalone bundle builds after
removing their stale trees manually. This release automates that repair.
