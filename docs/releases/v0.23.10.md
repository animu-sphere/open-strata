# v0.23.10 - Imaging bundles on locked usd runtimes

## Objective

Fix [USD VRM Plugins report 50](https://github.com/animu-sphere/usd-vrm-plugins/blob/main/docs/reports/ost/50-2026-09-26-v0.23.9-the-imaging-kind-arrives-and-the-usd-profile-cannot-select-it.md):
v0.23.9 required a viewer profile before it could inspect the imaging SDK,
blocking bundles on the published canonical `usd` runtimes.

## Shipped changes

- `usd-imaging` no longer implicitly requires `hydra-preview`. Build preflight
  and L1 `runtime.usd_imaging` still require the resolved runtime's usdImaging
  header and library; a core-only SDK cannot build or validate adapters.
- Template `usd-imaging-cpp` 0.1.1 declares `usd-stage-read` and documents the
  SDK requirement. Imaging variants of `usd` can build, test and package the
  bundle without selecting `lookdev` or replacing the project's runtime lock.
- Explicit descriptor capability requirements remain enforced. Native L2
  adapter construction, schema closure and package runtime identity checks
  retain their existing contracts.

## Migration and limits

Remove `hydra-preview` from `requires.capabilities` in a v0.23.9 scaffold or
hand-authored imaging descriptor unless the plugin independently needs that
capability. Keep the project's `usd` profile and locked imaging runtime.
There is no canonical runtime republish, profile catalog change or lock bypass.

The CLI and workspace crates are `0.23.10`. Native registry checks still need
CMake, Ninja and a C++ compiler. Report 50's baseline session/frozen type update
belongs to usd-vrm-plugins; native downstream Linux/macOS acceptance and report
48's producer RUNPATH cleanup remain open.

See the [verification report](../reports/2026-09-26-v0.23.10-imaging-usd-profile.md).
