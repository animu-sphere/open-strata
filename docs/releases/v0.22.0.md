# v0.22.0 - OpenUSD artifact compatibility and trusted distribution

## Objective

v0.22.0 turns OpenUSD build, artifact, and OCI surfaces into one explicit
compatibility policy. An approved build cell now carries its VFX Reference
Platform profile, platform and architecture, toolchain and native-runtime
boundary, Python and TBB providers, graphics variant, exact source and dependency
identities, independent verification state, SBOM, provenance, and immutable
artifact digest from producer to consumer.

## Completed capabilities

- **Normalized OpenUSD compatibility identity.** Schema-versioned runtime and
  artifact records carry resolved compiler, C++ standard, glibc/CRT, Python,
  oneTBB, platform, architecture, variant, and capability dimensions. Approved
  Linux x86_64 `headless`, `standard`, and `vulkan` cells are data-driven;
  protected compatibility inputs cannot be silently overridden.
- **Deterministic selectors and consumer gates.** Normalized identities derive a
  source/dependency-bound OCI-safe selector. Resolution exposes the selector and
  digest-pinned pull re-derives it before import. `--require-openusd` and
  `--require-openusd-version` reject platform, ABI, provider, version, and
  graphics mismatches before launch with dimension-specific diagnostics.
- **Resilient, observable OCI pulls.** Layer downloads have separate connect,
  response-header, body-idle, and optional overall timeouts, with bounded retry,
  validated range resume, digest verification, and seven-day partial cleanup.
  Human and JSON results include the OCI manifest plus ordered per-layer transfer
  attempts; generated CI caches only a fully verified digest-keyed registry.
- **Evidence-gated trust.** Digest-pinned pull can require valid SPDX SBOM and
  SLSA/in-toto provenance sidecars, enforce an explicit or policy trust floor,
  and match approved publisher identities. Missing, invalid, or insufficient
  evidence leaves no usable artifact behind.
- **Exact managed build provenance.** A clean OpenUSD checkout contributes its
  credential-free origin and exact commit. Managed `build_usd.py` downloads are
  captured by selected dependency name, repository/revision/version, and archive
  SHA-256. CY-compatible oneTBB sources are pinned instead of inheriting upstream
  defaults, and conflicting metadata fails before packing.
- **Independent graphics verification.** Compile, link, loader, physical-device,
  and render are separate digest-significant states. Runtime validation loads the
  required OpenGL/Vulkan APIs, creates native GLX/Vulkan device observations,
  and runs OpenUSD's `usdrecord` against a generated sphere. A later state is
  never inferred from an earlier pass; unavailable headless prerequisites remain
  `not-run`, and immutable consumers cannot overwrite producer evidence.
- **Producer and workspace closure.** Runtime export measures the actual native
  runtime floor, retains the SDK layout, captures source/dependency identity, and
  re-runs current validation before packing. Explicit workspace membership,
  root-build bundle provenance, descriptor-scoped library lifecycle commands,
  managed workspace-tool staging, and runtime-drift diagnostics close the
  packaging paths exercised by the reference projects.
- **Renderer and smoke-test truth.** Managed renderer timeouts and success/failure
  launch records are durable and producer-bound. Smoke fixtures accept strict
  OpenUSD file-format arguments, enabling direct PLY verification without a USDA
  wrapper.

## Compatibility notes

- Linux x86_64 is the first approved normalized build target. Legacy targets
  without an approved cell remain readable and retain the unclassified build
  path unless a caller explicitly claims a variant.
- The release acceptance cell used OpenUSD 26.05 at source revision
  `2095fafafd033fa23386d7ec6d58c7cc33974518`, GCC 14.2, C++20, CPython 3.13.15,
  oneTBB 2022.1.0, and the Vulkan variant on Ubuntu 24.04. The packed target
  measured glibc 2.38 while the normalized CY requirement remained the compatible
  floor `>=2.28`.
- OpenUSD 26.05's `usdrecord` needs an auxiliary Qt/OpenGL display even when Hgi
  renders through Vulkan. The Linux producer keeps an isolated Xvfb display alive
  through validation and export; `HGI_ENABLE_VULKAN=1` fixes the actual render
  backend.
- DCC host adapters, Maya `.mod` and Houdini package generation, and the pinned
  host support matrix are intentionally deferred to v0.23.0. v0.22.0 models the
  provider and requirement data they consume but does not launch a DCC.

## Evidence

- The workspace release gates cover formatting, Clippy, tests, generated docs,
  documentation links and consistency, licenses, and cargo-dist planning.
- **Linux Vulkan acceptance exercised 2026-08-15:** the producer passed schema,
  digest, layout, tool, Python, consumer CMake, OpenGL/Vulkan loader,
  OpenGL/Vulkan device, and actual-frame checks. Mesa llvmpipe supplied the
  OpenGL renderer, Vulkan enumerated one physical device, and `usdrecord` wrote a
  non-empty 64-pixel Vulkan frame.
- The temporary public tag resolved anonymously to OCI digest
  `sha256:8179a10d88387c271421e36e9e1b2b97fc028b9d85eb5e48d8bbaed8f619c16d`.
  A clean, unauthenticated store pulled that immutable digest and verified the
  expected OpenStrata artifact digest
  `sha256:209756bb6a0857e16770f5d9c0691c7b46086663634e74a83dc4517dcd93d879`,
  selector, runtime kind, OpenUSD 26.05 Vulkan requirement, every file digest,
  SBOM, and provenance before import. The dedicated acceptance package was then
  deleted and the GitHub Packages API returned `404 Package not found`; these
  digests are retained as historical evidence, not as downloadable release
  artifacts.

## Known limitations

- The normalized release matrix is deliberately constrained; it is not the full
  OpenUSD × CY × Python × graphics × operating-system Cartesian product.
- Graphics device/render observations require usable host drivers and, for the
  current Linux OpenGL path, a display. Missing prerequisites remain explicit
  `not-run` evidence rather than a manufactured pass.
- Mutable OCI tags are discovery conveniences only. Reproducible consumers must
  resolve a readable tag and retain the immutable OCI digest plus the expected
  OpenStrata artifact digest.
