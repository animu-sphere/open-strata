# v0.22.7 - Locked composed runtime and native SDK

## Objective

Turn the v0.22.4 resolved component model into a portable, locked composition
that reconstructs from immutable artifacts, exports independently, and provides
a relocatable native SDK with verified activation and CMake consumption.

This release combines the locked-runtime implementation from
[PR #202](https://github.com/animu-sphere/open-strata/pull/202) and the SDK slice
from [PR #203](https://github.com/animu-sphere/open-strata/pull/203), originally
planned for v0.22.8. The following milestones move forward one slot: geospatial
dogfood v0.22.8, consumer packaging v0.22.9, and runtime UX/diagnostics v0.22.10.
DCC host adapters remain v0.23.0. Earlier released records retain their original
planning history.

## Implemented capabilities

- `runtime compose --lock`, `--locked` and `--output` preserve exact provider,
  producer metadata, source/dependency, compatibility, environment, install and
  file-ownership decisions. The lock is a versioned JSON contract.
- Runtime identity combines canonical inputs and complete payload inventory,
  including symlinks and executable bits. Acquisition locations and importer
  state do not contribute identity. Manifest candidate order is canonicalized.
- `runtime reconstruct` consumes a lock without the original manifest or caches;
  missing inputs use pinned OCI or digest-checked filesystem distributions.
- `runtime export --composition` creates a distinct `composed-runtime` artifact
  with selected component payloads, retained metadata/evidence, attribution,
  exact-dependency SPDX SBOM and unsigned local composition provenance.
- `runtime reconstruct --from-artifact` restores an exported composition without
  the original component store. `runtime validate --composition` verifies the
  locked graph, inventory and retained evidence.
- Staging and rename keep incomplete outputs out of final prefixes. Existing
  destinations are refused. Metadata-only drift, payload tampering, missing or
  extra files and forged validation reports fail with coded diagnostics.
- New locks compare declared source metadata and evidence against warm caches
  without downloading the archives again. Locked cache reuse remains offline.
  Overlapping external lock/output paths and exported dependency identities
  inconsistent with the embedded lock are rejected before output publication.

### Native SDK and activation

- New locks include an owner-recorded SDK projection and portable Formation
  environment contributions. Public `bin`, `lib`, `include`, `share`, `plugins`,
  `python`, `node`, and `metadata` roots survive export and reconstruction.
- Producer install mappings expand against the verified inventory. File and
  ancestor collisions, reserved roots, missing sources and ambiguous/uninstalled
  symlink targets fail before publication. Relative symlinks are remapped.
- Component prefixes and producer evidence remain intact. SDK copies are
  independent and verified, including modes, symlink bytes and ownership.
- `runtime env --composition` emits a verified isolated environment as JSON or
  escaped Bash/PowerShell statements. Activation and execution disable Python
  bytecode writes and user-site imports; legacy Python layouts are discovered
  from locked inventory when producers omit `PYTHONPATH`.
- `runtime exec --composition -- <command>` checks host compatibility, resolves
  bare executables on SDK PATH, resets runtime search paths, propagates exit
  codes and records process results under `--json`.
- `runtime validate --composition --sdk` checks activation, plugin library and
  resource paths, and schema-resource reachability. Repeatable `--cmake-package`
  explicitly configures installed CMake packages in a fresh restricted prefix.
  Absent conventional plugin `lib`/`python` search directories are optional;
  declared plugin libraries and schema resources remain required.

## Compatibility

- Legacy OpenUSD runtime artifacts and CY/profile commands keep their existing
  contracts. Older OST versions do not recognize `composed-runtime` artifacts.
- Component prefixes are preserved under `components/<id>` alongside the SDK.
  Component-only locks from unreleased drafts omit `sdk` and retain their
  original identity/layout when rebuilt, exported or checked with `--locked`.
  Recompose without `--locked` to opt into the SDK identity. Earlier draft
  binaries cannot read SDK-bearing locks; SDK locks from intermediate drafts
  must also be recomposed to record the corrected activation paths/settings.
- Composition structure/inventory success is not runtime execution success.
  Producer observations remain separate, execution probes report `not-run`,
  and exported runtime validation remains `pending`.
- Provider metadata is pinned separately from archive bytes. Republishing
  changed metadata for the same archive cannot satisfy an existing lock.
- No dependency, toolchain or canonical OpenUSD artifact changes are required.

## Verification and known limitations

- Windows workspace tests and clippy passed locally; the integration suite
  exercises separate producer/consumer stores, clean lock reconstruction,
  self-contained export consumption, repeatable export and negative cases.
- Fixtures use real small archives and the real artifact transport. They do not
  claim real OpenUSD execution or geospatial acceptance.
- The release CI gate runs the composition suite on Linux, Windows, Apple
  Silicon macOS and Intel macOS. SDK tools are mandatory in that gate; missing
  CMake, Ninja, a compiler, Python or the activation shell cannot silently skip
  the corresponding execution coverage. Unix runs cover symlinks and modes.
- A native C++ fixture builds a shared library and installed executable,
  exports the SDK, removes producer build/install trees, reconstructs into a
  separate artifact store and relocates the prefix. A separate consumer resolves
  `find_package(Tiny CONFIG REQUIRED)`, builds and runs with SDK loader paths.
  Python imports and rendered activation run repeatedly across four producer
  layouts; codeless schema and metadata/ownership tampering regressions are covered.
- The SDK preserves declared producer paths; it does not patch CMake configs,
  plugInfo metadata, RPATH or DLL references. Extra SDK copies increase artifact
  size. Producers must provide discovery paths and relocatable installs.
- `runtime exec` is not an OS isolation/security sandbox. Explicit CMake package
  probes execute component code and must be used only with trusted components.
- Tiny SDK and structural plugInfo/schema checks do not establish real OpenUSD
  plugin/resolver registration, schema behavior, GPU availability or rendering.
  Component-owned OpenUSD probes and independently published geospatial
  clean-consumer acceptance remain explicit v0.22.8 dogfood gates. They are not
  claimed as completed by this release. Export validation remains `pending`.
