# v0.22.3 - Canonical OpenUSD runtimes and component artifact contracts

## Objective

v0.22.3 establishes one normalized model for the canonical OpenUSD 26.05/26.08
CY2026 runtime matrix and closes the component-artifact boundaries needed to
compose independently owned runtime inputs without flattening their ownership.

## Completed capabilities

- **Canonical OpenUSD runtime model.** Separate `profile = usd` from normalized
  `core`, `gl`, `vulkan`, and `metal` variants; model the 18 primary Linux
  x86_64, Windows x86_64, and macOS arm64 leaves from one deterministic support
  declaration.
- **Version-aware build planning.** Centralize compatibility-critical OpenUSD
  build options in `OpenUsdBuildPlan`, including mandatory upstream examples for
  imaging variants and version-specific `build_usd.py` behavior.
- **Cross-platform producer and verification adapters.** Generate platform-local
  build, validation, SBOM, provenance, OCI publication, and clean-pull commands
  while preserving independent compile, link, loader, device, and render
  evidence.
- **Normalized compatibility and transport identity.** Record exact OpenUSD,
  provider, toolchain, ABI, capability, and macOS SDK/deployment facts; keep
  selectors, immutable digests, and human leaf tags as distinct contracts.
- **Non-leaf library composition.** Resolve validated `requires.libraries`
  closures, build prerequisites into owner-specific prefixes, expose them through
  normal CMake discovery, and bind test/package operations to dependency build
  evidence.
- **Explicit aggregate products.** Let workspaces declare exact release members
  and exclusions, fail on membership drift, and print the resolved set in human
  and JSON output.
- **Project-owned shared data.** Stage verified project-relative data mappings
  below `share/` and restore them through aggregate artifact install without
  assigning the payload to an unrelated tool.
- **Template hygiene.** Emit shared clang-format and gitignore contracts across
  C++ scaffolds and verify generated templates in CI.

## Compatibility notes

- Legacy `standard` graphics input normalizes to `gl` with a migration warning.
  Older runtime and artifact records remain readable; modern selectors use the
  versioned compatibility facts when present.
- Runtime profile and graphics variant are now independent compatibility axes.
  Consumers should request `profile = usd` plus the required normalized variant.
- Aggregate workspaces can omit `release_members` for the previous discovery-
  driven behavior. Release lanes should declare it to detect unintended product
  changes.
- Shared-data mappings accept project-relative sources and destinations below
  `share/`; traversal, globbing, and ownership collisions are rejected.

## Known limitations

- The 18-leaf planner and publisher integration are covered in CI, but the full
  host-specific OpenUSD builds, protected GHCR publication, and clean
  pull-by-digest pass are post-release validation work. Any corrections found by
  that pass will ship in v0.22.4.
- USD VRM release-lane dogfooding with a v0.22.3 binary remains a downstream
  post-release validation step.
- Canonical leaf tags are the publication unit. OCI multi-platform aliases remain
  deferred until deterministic index transport is proven.
- DCC host adapters and the pinned host support matrix remain deferred to
  v0.23.0.
