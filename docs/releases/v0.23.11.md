# v0.23.11 — Packaged renderer Formations

Addresses hydra-toon report 04 and OpenStrata issues #251–#255.

## Changes

- Formation matches package targets by platform, OS, architecture, Python and
  profile. ABI compatibility remains separately checked; target prefix collisions
  and mismatched profiles are rejected.
- `ost package --intent hydra` packages the completed `build/<target>--hydra`
  tree, validates it against the current declaration, and records the complete
  build intent in provenance. Named intent archives use distinct dist paths.
- Renderer discovery paths come from installed `plugInfo.json` files, including
  the template's `lib/usd/hd<Name>/resources` layout.
- Build/configure and plugin build write the same selection-specific lock.
  The project's default selection keeps `strata.lock`; other selections use
  `strata.<runtime-id>.lock`. `ost lock --profile <name> [--check]` and plugin
  packaging select that same file, preserving the workspace's default pin.
- The canonical producer supports OpenUSD 26.08 `lookdev` GL leaves for Windows
  and Linux x86_64, including usdview, bundled PySide6/PyOpenGL, source identity,
  runtime validation, import probes and anonymous digest-pull verification.
- `runtime explain` reports installed extension versions and runtime validation.
  It does not reuse catalogue certification for a different installed version.
  The OpenUSD allowed range includes 26.08.

## Compatibility and verification

Existing default-profile commands retain their paths. To intentionally change
the workspace's default profile, edit `openstrata.toml` and run `ost lock`.
Commit secondary profile locks when CI should enforce those selections too.

Regression coverage packages a real CMake install tree with a named intent and a
codeless schema using the CLI, then imports both artifacts and resolves/locks a
Formation. It also covers wrong platform/architecture/Python/profile identities,
installed plugin paths, stale intent declarations, profile lock isolation and
installed-runtime version reporting. These fixtures test the composition
contract; downstream VRM rendering remains a separate acceptance measurement.

macOS lookdev is not added to the canonical matrix without usdview evidence.
See the [canonical producer guide](../guides/publishing-canonical-openusd-runtimes.md).
