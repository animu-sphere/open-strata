# v0.23.21 — plugInfo LibraryPath from the CMake target

The copied CMake helper now derives each plugin's `plugInfo.json`
`LibraryPath` from its CMake target. This release also fixes four template
failures that stopped fresh scaffolds from passing `ost plugin test`.
[PR #300](https://github.com/animu-sphere/open-strata/pull/300)

## LibraryPath from the CMake target

- Helper 1.2.0 adds `@OPENSTRATA_PLUGIN_LIBRARY_PATH@`. It expands to the
  relative path to the bundle's `lib/` plus `$<TARGET_FILE_NAME:target>`, so
  `OUTPUT_NAME`, `PREFIX`, `SUFFIX` and `DEBUG_POSTFIX` on the target are
  always reflected. On Windows the name is the DLL.
- Each build configuration gets its own build-tree `plugInfo.json`, and
  install picks the one that matches. The source-tree file holds the primary
  configuration and is still where `ost plugin build` merges co-hosted schema
  Types.
- Configure fails if the install destination depth would break the relative
  path.
- `usd-fileformat-cpp` 1.3.0 uses the token. `ost plugin new` writes a
  host-specific preview so `inspect` and L0 `doctor` work before the first
  build.
- Native OpenUSD discovery was checked on an extracted package without `ost`.
  `plugin/resources/<name>/` and `plugin/<name>/resources/` behave the same,
  so the templates keep the current layout. See
  [plugInfo.json layout and library naming](../reference/template-catalog.md#pluginfojson-layout-and-library-naming).

## Template fixes

- `usd-fileformat-cpp` accepts OpenUSD 26.x runtimes. Its range was
  `<26.0`, so fresh scaffolds failed L1 on every 26.x runtime.
- Codeless schemas and schemas added with `ost plugin schema add` now pass L2
  `schema.registration` and L4 `schema.apply_roundtrip`:
  - Scaffolds write `class "<Name>API"` with `className = "API"`, so the
    schema identifier matches the TfType name. Two such bundles can now load
    together.
  - L2 and L4 look schemas up by identifier, as the registry does.
  - The co-hosted `generatedSchema.usda` is copied beside every installed
    `plugInfo.json`, so the type registers with its properties.
  - `schema add` adds a fixture that applies the schema, and L4 searches every
    smoke fixture.
- `schema add` sets `fileName` so a class named `API` no longer generates
  `aPI.h` over usdGenSchema's `api.h` export header on Windows and macOS. A
  new L0 `schema.generated_file_names` check and a build preflight name the
  fix for existing bundles.
- `usd-asset-resolver-cpp` no longer overflows the stack on the first
  identifier request. When a probe crashes, level failures report the exit
  status instead of a blank reason.

## Compatibility

Legacy prefix/suffix tokens resolve as before. Existing bundles keep their
pinned helper and keep working. The
[template catalog](../reference/template-catalog.md#pluginfojson-layout-and-library-naming)
describes the opt-in migration to helper 1.2.0.

Template versions: `usd-fileformat-cpp` 1.3.0, `usd-schema-codeless` 1.1.2,
`usd-asset-resolver-cpp` 0.3.2, and `usd-exec-cpp`, `usd-imaging-cpp`,
`usd-package-resolver-cpp` and `usd-schema-cpp` 0.1.2.

## Known limitations

- `usd-exec-cpp` and `usd-imaging-cpp` were not run against an OpenUSD
  runtime. The other C++ templates and a co-hosted schema passed build, test
  and package on Windows with OpenUSD 26.08. Linux and macOS are covered only
  by CI, which has CMake but no OpenUSD.
- `ost plugin new` accepts names that collide with OpenUSD classes. For
  example, an asset resolver named `ar` generates `ArResolver` and fails to
  compile.
