# v0.23.18 — Consumer-declared host dependencies without runtime republishing

Fixes [issue #289](https://github.com/animu-sphere/open-strata/issues/289):
the published Linux `cy2026` / `usd` runtime has no host package declarations,
so v0.23.17's X11/Xt discovery remained disabled for consumers pinned to it.

## Changes

- `ost library verify-consumer` accepts repeatable `--host-package` declarations
  using the existing `apt:PACKAGE` / `brew:FORMULA` syntax. Invalid names and
  package managers incompatible with the target OS are rejected before building.
- On Linux, `apt:libx11-dev` and `apt:libxt-dev`, declared by the runtime,
  the check, or both, enable the existing bounded X11/Xt discovery. For example:

  ```bash
  ost library verify-consumer libs/avatarVrmSession \
    --host-package apt:libx11-dev --host-package apt:libxt-dev
  ```

- The runtime manifest, digest, lock and pinned library artifacts are unchanged.
  No runtime or owner package republishing is required for this check.
- `library-consumer.json` adds `consumer_host_requirements`, sorted and
  deduplicated separately from the original `runtime_host_requirements`.
  Resolved host target paths remain in `runtime_host_paths`, including on
  later configure failures.
- Linux native regressions cover empty runtime declarations, missing or partial
  consumer declarations, successful linking, unchanged runtime identity, and
  rejection of unrelated paths, modified X11 targets and ambient packages.

## Compatibility and limitations

Packages must already be installed. This option declares dependencies for the
consumer check; it does not install them or infer a CI cell. In source CI,
provision the same packages through `host_packages.apt` and pass the options to
the consumer command. Only the X11/Xt pair enables extra host discovery; other
packages do not receive path allowances. Windows has no supported host package
manager for this option.

The regression uses synthetic package configs and real system X11 libraries.
Acceptance of the original downstream package still requires a hosted rerun with
its existing locked OpenUSD runtime and the explicit consumer declarations.
