# v0.23.2 - The root build composes external libraries

## Objective

Let a workspace whose members consume a digest-pinned library from another
repository build from its root CMake tree, which is what its generated CI runs.

## Shipped fixes

- `ost configure`, and so `ost build`, now prepend every external library
  artifact declared by the workspace's members to `CMAKE_PREFIX_PATH`, as
  `ost library build` and `ost plugin build` already did for one member's
  closure. The root CMake tree configures every member in one pass, so a
  member's `find_package` for an external package runs there too; before this
  the root toolchain named only the runtime and such a workspace could not
  configure at all, although the artifact was materialized beside it. A
  workspace that declares no artifact pin resolves to an empty set and its
  toolchain is unchanged.
- A library artifact built against another runtime now reports both identities
  — the runtime the artifact records and the one the target selects — and
  points at materializing the artifact's runtime. The previous message said
  only that the runtime differed.

## Compatibility

- Workspace crate and CLI versions are `0.23.2`.
- Existing v0.23.1 runtime, artifact, workspace and lock identities remain
  valid. No republish, re-pin or descriptor change is required.
- A workspace with no `requires.libraries` artifact pin generates a
  byte-identical `toolchain.cmake`.

## Known limitations and follow-through

- The downstream acceptance of the external library edge is now unblocked and
  still outstanding: `usd-vrm-plugins` switching nine members to
  `usd-motion-plugins` packages, and an independent installed consumer.
- The limitations carried by [v0.23.0](v0.23.0.md) and [v0.23.1](v0.23.1.md)
  are unchanged: producer-local paths in previously published OpenUSD
  artifacts, hosted macOS evidence for optional OpenUSD selectors, and the DCC
  host matrix.

## Downstream evidence

Reported and reproduced by
[usd-vrm-plugins ost report 43](https://github.com/animu-sphere/usd-vrm-plugins/blob/main/docs/reports/ost/43-2026-09-20-v0.23.1-the-root-build-cannot-see-an-external-library.md),
from the first real consumption of a cross-repository library artifact:
`motion-connectors` imported `motionTracking` and declared
`usd-motion-plugins`' `motionCore` as an external dependency. Everything else
in that edge worked — the declaration, `ost library pull`, the archive,
identity and runtime checks, the graph edge, the link and the tests — and the
root build was the one step that did not. The fix is verified against that
workspace: its root `ost build` completes and its suite passes.
