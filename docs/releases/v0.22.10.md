# v0.22.10 - Runtime correctness, UX and diagnostics

## Objective

Make composed runtimes ordinary to use and make identity, resolver and managed
build failures diagnosable without reconstructing hidden producer state. Close
the reusable correctness work found by the audit of all 71 downstream OST
reports while preserving one canonical digest-pinned runtime identity.

## Shipped capabilities

- Rewrote exported OpenUSD CMake package metadata in-memory so extracted SDKs
  resolve Python from the consumer and do not retain producer-absolute Python
  executable, library or include paths. The producer runtime remains unchanged,
  and the artifact manifest records the relocation policy and rewritten files.
- Added semantic `ost lock --check`: parsed locks are normalized before
  comparison, while runtime identity drift still fails in the validation exit
  category. Locks may now retain the runtime source, and plugin/product package
  flows reject a selected or recorded runtime that differs from `strata.lock`.
- Made workspace graph-only validation work for library/tool-only repositories,
  while preserving the historical bundle count and adding explicit member,
  library and tool totals to structured output.
- Changed resolver Level 2 to an offline registration/dispatch probe and added
  bounded status, stdout, stderr and detail evidence to plugin diagnostics.
- Added shared project `[build.cache]` inputs for root and scoped builds,
  project-relative path materialization, and safe external toolchain chaining
  through the generated OST toolchain.
- Added a single bounded JSON snapshot at the first managed-build stall,
  including thresholds, process descendants, tool versions, watched-file
  metadata and log tails without serializing the environment.
- Documented the workspace product JSON contract: `.data.product` is always
  present and is `null` unless `--product` selects aggregate verification.
- Revalidated the ordinary `runtime compose|explain|doctor|exec` surface,
  distinct verification claims, exact-identity native/Python/npm consumers and
  mixed root/scoped producer provenance through the complete workspace suite.

## Compatibility

- Workspace crate and CLI versions are `0.22.10`.
- v0.22.9 runtime, artifact, lock, consumer-package and aggregate-product
  identities remain valid. The lock `runtime.source`, project `build.cache` and
  plugin-report `probe` fields are additive; older locks and manifests continue
  to parse.
- `ost lock --check` now compares semantic lock content rather than formatting
  and returns exit code `5` for stale, missing or malformed lock state.
- The new stall snapshot uses the versioned
  `openstrata.stall-diagnostic.v1` schema and is written beside the build log or
  below `.strata/diagnostics`.

## Known limitations

- Runtime-free and per-cell intent-aware CI, pyramid/package release verbs,
  generated/hand-authored lane reconciliation, stale generated workflow
  detection and per-member test attribution remain v0.23.0 work.
- The first-class `usdview` host-add-on model and DCC adapter matrix remain
  v0.23.0 work. OpenStrata does not install, license or mutate host applications.
- External ecosystem publication is not claimed as release evidence; consumer
  packages remain registry-neutral derived views whose dependency truth is the
  canonical OST artifact identity.

## Verification

The release gate passed locked workspace unit, lifecycle, runtime-artifact,
runtime-composition and documentation tests; clippy with warnings denied;
deterministic CLI/schema reference generation; link and documentation-consistency
checks; and diff hygiene. Native lifecycle coverage remains host-capability
dependent as documented in the root README.
