# v0.22.4 - Runtime component model + canonical matrix corrections

## Objective

v0.22.4 is the first composition slice built on the v0.22.3 canonical runtime
foundation: several independently published artifacts resolve into one
deterministic runtime component model, and every conflict is diagnosed before a
single payload file is written. It also carries the corrections found by the
v0.22.3 post-release validation pass on real hosts.

## Completed capabilities

- **Versioned component contract.** `openstrata.component/v1alpha1`
  ([`schemas/component.schema.json`](../../schemas/component.schema.json))
  normalizes runtime, plugin, library, tool, renderer, and data
  requirements/provisions, target/ABI/OpenUSD compatibility, environment
  contributions, and install ownership into artifact records — without forking
  the existing plugin activation or Formation models.
- **`ost runtime compose`.** A read-only resolve of a versioned composition
  manifest
  ([`schemas/runtime-composition.schema.json`](../../schemas/runtime-composition.schema.json)):
  it verifies digest-pinned candidates and emits a canonical
  `openstrata.runtime-composition-resolved/v1alpha1` model with a composition
  digest, ordered components, provider decisions, environment, and install
  ownership. `--json` output is stable.
- **Deterministic provider selection.** Capabilities resolve to providers
  deterministically, with explicit `[providers]` pins for release-critical
  singleton capabilities.
- **Pre-materialization diagnostics.** Coded `COMPOSITION_*` failures for
  missing providers, version/ABI/OpenUSD conflicts, singleton capability
  collisions (including a non-singleton co-provider), install-path collisions
  (after path normalization), and incompatible environment operations — all
  before archive extraction.
- **Canonical matrix corrections.** The post-release validation pass on real
  hosts fixed: an operator-plus-wildcard version constraint that made CY2026's
  `libcxx: "17.x"` unsatisfiable and blocked all six macOS leaves; a macOS
  relocation check that rejected the contract's own platform CPython; Mach-O and
  ELF floor scanners aborting on linked directories inside framework bundles; an
  OpenUSD cleanliness check tripping on `build_scripts/__pycache__/` residue
  from the previous leaf; a producer re-run unable to re-export an already
  exported leaf; and a skipped device probe failing validation while displaying
  as `[skip]`.
- **Producer platform fixes.** Windows canonical builds use Ninja and retain the
  inherited MSVC toolset identity, Windows gained a physical OpenGL device
  probe, and the Linux producer image ships `pwsh` and trusts a mounted
  checkout.

## Compatibility notes

- The canonical matrix is now **16 leaves**, not 18. macOS declares `core` and
  `metal`; the macOS `gl` lane is refused at plan time because OpenStrata
  implements no physical OpenGL device probe on macOS, so such a leaf could
  never satisfy the export gate. The gate itself is unchanged — a lane that
  could not pass it was removed. Reinstating `gl` on macOS means implementing a
  CGL-based headless device probe first.
- A graphics device probe that could not run now maps to a passing, skipped
  check, matching the documented rule that a skipped check never fails
  validation. A probe that ran and failed still fails, and `render_backend_ready`
  is still computed from the probes themselves.
- The macOS relocation exemption is derived from the runtime's own manifest: only
  a CPython of the recorded series, and only when the manifest declares
  `python: { provider: platform }`. Build-prefix and package-manager leakage
  still fails.
- `ost runtime compose` resolves only. Locking, materializing, and exporting a
  composed runtime are later v0.22.x slices.

## Known limitations

- Cross-repository acceptance is post-release work: the real published-artifact
  pass in `usd-geospatial-runtime`, and the Linux and Windows halves of the
  canonical 16-leaf build, publication, and clean digest-pull validation. The
  four macOS leaves are published. Corrections found by that pass ship in
  v0.22.5.
- Composition is verified against a synthetic multi-artifact graph on Windows,
  Linux, and macOS plus the checked-in geospatial fixture, not yet against
  independently published real artifacts.
- USD VRM release-lane dogfooding with a released binary remains a downstream
  step.
- DCC host adapters and the pinned host support matrix remain deferred to
  v0.23.0.
