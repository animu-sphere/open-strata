# v0.23.19 — macOS framework Python development artifact resolution

Fixes [issue #291](https://github.com/animu-sphere/open-strata/issues/291):
`ost library verify-consumer` could report `runtime_python: null` on macOS with
a framework Python, rejecting the Python include path exposed by OpenUSD's
exported targets.

## Changes

- Python development discovery now resolves framework-relative `LDLIBRARY`
  paths against `PYTHONFRAMEWORKPREFIX` when `PYTHONFRAMEWORK` is declared. It
  also checks the framework's versioned binary when `LDLIBRARY` is a basename.
  Existing `LIBDIR` and multiarch candidates retain priority; Windows continues
  to resolve the import library beneath `sys.base_prefix`.
- Framework discovery prefers the versioned `libpythonX.Y.dylib` alias when
  present so CMake can infer its version. When that alias is a symlink to the
  framework binary, link-directory checks use the selected alias directory;
  file checks still resolve to the exact binary.
- Only existing library files qualify. Missing libraries and directories do
  not produce development hints. The interpreter version and include-directory
  checks remain in force.
- Installed consumers use the resolved Python include tree and exact library
  file through the existing bounded path allowances. No general framework,
  library-directory or ambient package allowance is added.
- Layout regressions execute the same Python probe embedded in `ost`. Hosted
  native SDK CI runs the probe and the installed-consumer regression on Linux,
  Windows and both macOS architectures. macOS uses `actions/setup-python` 3.13
  and requires framework Python; the consumer regression cannot silently skip
  missing tools or Python development artifacts in this lane.

## Compatibility and limitations

No CLI, report schema, runtime identity or package contract changes are required.
Existing pinned runtimes can use the corrected host Python resolution without
republishing. A matching host Python with development artifacts must be installed.

The installed-consumer regression uses synthetic OpenUSD package metadata and
real host Python development artifacts. Acceptance of the original downstream
libraries still requires a hosted rerun with their locked OpenUSD runtime.

See the [workspace reference](../reference/plugin-workspace.md).
