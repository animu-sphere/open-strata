# v0.23.0 - Release CI, component closure and host add-ons

## Objective

Carry the canonical, digest-pinned runtime identity into generated and
externally managed CI, package each workspace library from its own installed
files, and give host add-ons and headless DCC launches explicit component and
execution evidence.

## Shipped capabilities

- Added runtime-free workspace source CI with declared build intents, cumulative
  workspace pyramid and package rungs, and detection of stale generated
  workflows. An explicitly empty workspace now validates as a zero-member graph.
- Added `external_workflows` validation against the declared OST version,
  support cells and consumed `OST_CI_*` bindings. Workspace test JSON and
  managed completion evidence attribute CTest counts to discovered members and
  warn about testable members with no tests.
- Made optional OpenUSD selectors safe when absent under Bash `set -u`, across
  generated source and release lanes. Runtime validation distinguishes a
  CMake configure result from a C++ consumer that links and runs against the
  selected OpenUSD export.
- Kept member-specific installed-library snapshots for workspace builds.
  Library packages use the selected member's recorded files, enforce declared
  platform-specific required runtime files, and preserve exact dependency
  inventories through package and aggregate-product verification. Product
  activation deduplicates internal bundle paths after checking member identity.
- Added digest-pinned external library artifacts to `requires.libraries`, with
  per-target pins for multi-OS workspaces. The graph distinguishes external
  providers, generated source and release CI pull them explicitly, and build,
  test, package and product records retain their exact artifact identities.
  Materialization checks archive bytes, library/version/target identity, the
  canonical runtime id and digest, and each required library in the selected
  closure before adding CMake and loader paths.
- Added a first-class `usdview-plugin` source bundle and `host-addon` artifact.
  It participates in workspace build, package, product and Formation flows;
  static registration, real OpenUSD registry import and host launch produce
  separate verification claims.
- Added a Formation-pinned `ost host run` path for discovered Maya and Houdini
  installations. It checks recorded host identity and Python ABI before
  launching the selected headless executable, composes the host environment,
  and records host, runtime and component identities in run evidence.

## Compatibility

- Workspace crate and CLI versions are `0.23.0`.
- Existing v0.22.10 runtime, artifact and lock identities remain valid. New
  workspace CI, library runtime-file and host-add-on declarations are opt-in.
- Host execution requires a matching discovered host installation and a locked
  Formation. Host software remains installed and licensed by its owner.

## Known limitations and post-release work

- The `usd-motion-plugins` `motionCore` to `usd-vrm-plugins` migration and an
  independent installed consumer remain post-release downstream evidence.
- Member-specific package closure has source-level checks, but build-order
  independence and installed-product loadability across the three target OSes
  still need downstream runs, including a negative missing-file case.
- The consumer-link validator has not yet been exercised on a clean hosted
  consumer using a republished, digest-pinned OpenUSD artifact. The geospatial
  `sdk-usd` lane remains disabled pending that result.
- Hosted macOS evidence for empty and populated optional OpenUSD selectors is
  pending. Explicit selectors in the 3DGS matrix remain a workaround.
- Maya/Houdini host-specific smoke suites, package adapters, capability SKIPs
  and the full host/OS/OpenUSD/Python matrix remain incomplete.
- Release assets, attestations and installed CLI behavior will be checked
  after publication. Defects found in that pass will be addressed in v0.23.x.
